The purpose of these files are to read data from dbcontext.

Under Data/Repository folder:

**Generic repo interface:**
1. Create IGenericRepo.cs interface class of type <T> to accept any entity model type

**Notes:**
2. Add methods as Task<List<T>> which returns List to the called service, disconnecting connection to context from service

3. Add method as Task<T?> and pass Expression filter which returns 1 entity model object as response

4. Add method as Task for saving changes to context

5. Add method as Task<T?> with parameter as (int id) to fetch record by id from context, useful in delete action

6. Add method as Task with parameter as (T data) for create as we do AddAsync(entity)
	Keep it only Task because id is not yet generated and so we don't return the entity
	EFCore supports Async operation, hence can be async though not calling DB

7. Add methods as void with parameter as (T data) for update, delete as they are only for tracking
	These only modifies the state to modified or removed hence no async required

**Diff:**
IQueryable is used when filtering has to happen in DB on query execution and fetch result but query not yet executed
	All differed execution queries - which will run later with ToList or FirstOrDefault are of type IQueryable
	Used when we want to give access to caller to build queries

IEnumerable is used when all data are returned and stored as in memory collection, then filters
	Query is executed when we do ToList or FirstOrDefault only and when executed stores in memory
	Used when we want filtering happens in memory

List is used when we want to return list as materialized data and is concrete
	Concrete meaning we can create objects for it and modify
